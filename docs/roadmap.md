# Roadmap

Port of Police Chase: Drift from Unity to Godot 4.7 (GL Compatibility), as a web game. The Unity
project ([PoliceChaseDrift](https://github.com/tiago-xavier-braga/PoliceChaseDrift), cloned into
the git-ignored `unity/PoliceChaseDrift/` with its Git LFS files when needed) is the reference:
the Godot version must play the same. Improvements are not part of the port; they go to the
backlog. All project documentation must be kept in the `docs/` folder.

This project is vibe coded: items don't need a design note before code.

- [x] Set up the project: folders, input map (WASD / arrows / left stick), web export preset,
  `.claude` rules from Train Rush

- [x] Extract every FBX sub-mesh to its own resource (`tools/godot/extract_meshes.gd`)
- [x] Export a web build to make sure the pipeline works

## Porting notes

| Unity | Godot |
|---|---|
| URP, WebGL | GL Compatibility, web export |
| ScriptableObject data (`CarParameter`, `CarDatabase`) | custom `Resource` (`.tres`) in `resources/` |
| ScriptableObject event channels (`OnGameStateChanged`, `OnCarSelected`, `OnNightChanged`) | `GameEvents` autoload (signals + last value) |
| `PlayerHealth` ScriptableObject | `PlayerHealth` autoload |
| `PlayerData.CurrentCar` | `GameEvents.current_car_index` |
| Additive scene bundles (`Start` → `StaticEnvironment` + `Cutscene`/`Game` + `DynamicEnvironment`) | `lvl_cutscene.tscn` and `lvl_game.tscn`, each instancing both environment scenes; `Loading` autoload swaps them |
| Rigidbody + 4 WheelColliders | `VehicleBody3D` + 4 `VehicleWheel3D` |
| Timeline (`Opening.playable`) | one `AnimationPlayer` animation (`anim_opening.tres`) |
| Animator on parked cars | `AnimationPlayer` with `anim_parked_car.tres` |
| LeanTween | LeafTween (`addons/leaf_tween`) |
| URP decal projectors | flat quads (Compatibility has no decals) |
| Shader graphs (dissolve, stylized water) | `assets/shaders/*.gdshader` (the water is simplified) |
| UI Toolkit/uGUI canvases, `CanvasGroupController` | `game_ui.tscn` with `MenuPanel` controls |
| Unity scenes and prefabs | generated by `tools/unity_port/gen_godot.py` |

The generator writes the environment scenes, the car and prop scenes, the cutscene and both
levels from the Unity data. The scripts, the UI scene and the loading scene are hand-written.

Unity is left-handed and mirrors FBX models on X when importing them. The generator converts
every transform (z → -z) and turns FBX meshes 180° around Y, so the positions in the Godot
scenes match the Unity ones with the sign of z flipped. Cars use the same 180° turn as their
root frame, so they drive toward +Z as `VehicleBody3D` expects.

Physics conversions (in `gen_godot.py` and `car.gd`):

- Motor torque and brake torque are divided by the wheel radius (Godot takes forces); the brake
  is turned into an impulse per physics step.
- The suspension spring and damper are divided by the 1000 kg mass (Godot multiplies them by
  it). Wheel grip is a single `wheel_friction_slip` of 3.
- Physics runs at 50 Hz like Unity's fixed timestep, with physics interpolation on. The follow
  camera turns interpolation off for itself: it already reads the car's interpolated transform
  every frame, and interpolating it again made the car look shaky.
- The characters' `walk` clip loops (set in `police.fbx.import` / `thief.fbx.import`): the
  Timeline holds it for 5 s, and Godot plays imported clips once.
- Collision masks follow each Unity rigidbody's `m_ExcludeLayers`: the police car's excludes
  Building, so it drives through buildings (`UNITY_LAYERS` in `gen_godot.py`).
- The cutscene cars are disabled instances (no physics, no scripts) moved by the timeline, and
  every generated `AnimationPlayer` runs on the physics tick, so physics interpolation keeps
  them smooth.
- A car under 0.3 m/s counts as stopped and drives off instead of braking: Unity's resting
  rigidbody reads exactly 0, Godot's wheels jitter around it.

## Backlog

- Decide on the Unity quirks listed at the end of `gdd.md`.
- Lights: URP intensities don't map to Godot energies; the headlights (3) and lamps (6) were set
  by eye. Unity's flat ambient (intensity 1) and sun (1) blew the scene out in Compatibility; the
  port uses ambient 0.5 and sun 0.8 (`AMBIENT_ENERGY` / `SUN_ENERGY` in `gen_godot.py`). The Compatibility renderer, like URP, only lights each mesh with its 8 nearest lights,
  so the big floor tiles don't show every lamp.
- The loading screen's Unity sprite comes from a package missing in the repository; the port
  shows a plain color with the spinner.
- The cutscene ignores the speed of a few Timeline clips (0.8 on die, idle and emote-yes).
- The stylized water shader is a simplified version of the AureDevGames one (no depth foam,
  refraction or caustics).
